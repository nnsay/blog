# 声明

本文由 🤖AI 协作完成.

最近在为东盟国家的语言翻译需求选型开源模型。目标语言 8 种：印尼/马来语、泰语、越南语、缅甸语、高棉语、老挝语、他加禄语、英语，源语言以中文为主。硬约束只有两条——License 可商用、可自部署（vLLM / llama.cpp 常规栈）。

调研期间恰好撞上一次关键发布：11 月 23 日完成初版选型时，腾讯 Hunyuan 系还缺老挝语，我们准备了"Sailor2 补位"的组合方案；11 月 24 日腾讯开源 Hy-MT3（102 语言，新增老挝语），组合方案当场失去存在必要，全文推倒重写。这篇记录完整的选型过程和盲测实录，也顺便讲讲这次"撞上发布"带来的选型方法论收获。

# 1. 需求与难点

| 需求项   | 说明                                                                |
| -------- | ------------------------------------------------------------------- |
| 目标语言 | 印尼语/马来语、泰语、越南语、缅甸语、高棉语、老挝语、他加禄语、英语 |
| 源语言   | 中文为主                                                            |
| 硬约束   | License 可商用；可自部署                                             |
| 质量分级 | 高资源：印马/越/泰；中资源：他加禄；低资源：缅/柬/老（行业性难点）   |

低资源三语（缅/柬/老）是行业性难点，通用大模型在这几门语言上的表现普遍拉胯，可用的开源候选本来就不多。排查下来值得认真评估的是四家：Sailor2（Sea AI Lab）、Hy-MT2 / Hy-MT3（腾讯）、GemmaX2（小米）。所有关键信息均直接从 HuggingFace / ModelScope 官方模型页核实，非二手转述。

# 2. 候选模型逐一评估

## 2.1 Sailor2-8B / 20B（Sea AI Lab，新加坡）

Qwen2.5 底座上用 500B tokens（400B SEA 语料 + 100B 回放）持续预训练，15 种语言，8 种目标语言全覆盖，还带菲律宾地方语（宿务、伊洛卡诺、瓦瑞）。License 是 **Apache-2.0**，研究商用均无限制。技术报告实测 20B 与 GPT-4o 在 SEA 语言任务 50-50 胜率（自报数据）。GGUF 量化齐全，llama.cpp / Ollama 可跑。

短板在生态：月下载仅数千，小实验室项目，社区与 SLA 兜底弱。它的独特定位是**唯一"Apache-2.0 + 老挝语 + 通用对话能力"三者兼备的选项**——注意"通用对话"这一点，后面兜底方案会用到。

## 2.2 Hy-MT2-7B（腾讯）

腾讯 2026 年 5 月开源的纯翻译模型，36 语言、以中文为中心，Apache-2.0。质量证据是几个候选里最硬的：前代 Hunyuan-MT-7B 在 WMT25 受限组 31 个语向拿了 30 个第一，FLORES-200 33 语言 XCOMET 0.876，超过 Gemini-2.5-Pro——中↔东南亚方向最强的开源战绩。部署侧 FP8/GGUF 量化齐备，1.8B 小杯版量化后仅 ~440MB。

当时的问题只有一个：**老挝语不在支持列表里**。

## 2.3 GemmaX2-28-9B-v0.2（小米）

Gemma-2-9B 持续预训练 + SFT，28 语言全覆盖（含老挝语）。模型卡实测数据相当能打：FLORES+ zh→xx COMET 86.40 追平 Google Translate、反超 GPT-5；WMT24++ 与 GPT-5 差距不足 1 分。v0.2 换用小米最新一代 MiLMMT-46 指令体系微调，较 v0.1 全面提升（WMT24++ 79.21→84.19）。

但它的 License 排雷值得单独讲——这个坑很多选型文章不会告诉你：

> [!WARNING]
> gemma 许可"可商用"但**不是标准开源许可**：用途受《禁止使用政策》约束且 Google 保留远程限制权；分发权重有传导义务（要向下游传递使用限制 + 协议副本 + Notice）；违约终止后须删库。仅自用部署风险低；但**私有化交付给客户 = 分发权重**，上述条款全部触发，客户环境不可控。这类交付场景建议直接排除 gemma 许可的模型。

另外注意：这些实测分是 28 语言平均、厂商自报，缅/柬/老单项并未公开。社区也极小（月下载 ~100）。

## 2.4 Hy-MT3-1.8B / 7B / 30B-A3B（腾讯，2026-11-24 开源）

就在初版选型完成的第二天，腾讯开源了 Hy-MT3：102 种语言（前代 38 + 新增 64），**8 种目标语言全覆盖，老挝语为本次新增**，同批还补了爪哇/巽他/宿务/瓦瑞/僧伽罗等 SEA 语言。License 是 Apache-2.0。质量上官方称真实场景数据 vs MT2：误译降 43%、漏译/增译降 74%、指令遵循错误降 40%（自报，技术报告 arXiv 2611.27673）。

部署侧与 MT2 同三档（1.8B / 7B 稠密 + 30B-A3B MoE 仅激活 3B），每档都有 FP8 与 GGUF 变体。注意事项：transformers >= 5.6.0，vLLM / SGLang 目前需源码编译，llama.cpp GGUF 依赖较新的 STQ kernel。

它的定位一句话：**当前唯一"8 语言全覆盖 + Apache-2.0 + 大厂背书 + WMT 级质量血统"的单一翻译模型**。风险点也很明确——老挝语是新增语言、没有单项公开评测，上线前必须自建盲测。

顺带一提排除项，给同需求的人省时间：NLLB-200 是低资源翻译的质量标杆但 **CC-BY-NC 4.0 禁止商用**，直接排除；ALMA/ALMA-R 不含任何东南亚语言；SeaLLMs-v3 语言覆盖可以但自定义 license 商用需逐条审查；M2M-100-418M 许可干净（MIT）、CPU 可跑，只配当轻量兜底，质量低于新一代翻译 LLM。Typhoon/PhoGPT 等单语本土模型生态在萎缩（VinAI 已并入高通停更），不推荐当主力。

# 4. 选型结论：默认单模型

实际落地**默认只用一个模型**：Hy-MT3-7B 覆盖全部 8 种目标语言。

为什么不是预先拼组合？核心逻辑是成本对称性：每多一个模型就多一份显存/GPU 占用、推理服务和运维人力。Hy-MT3 补上了 Hunyuan 系最后一块短板（老挝语），使"质量最硬的"同时成为"覆盖最全的"——一个部署、一套推理栈、一份许可，工程与法务复杂度最低。组合方案只在**盲测证明必要时**才值得付出成本，而不是预先拼装。

GemmaX2 的出局前面讲过了：私有化交付即分发权重，gemma 许可的传导义务 / 终止风险 / 远程限制条款在客户环境不可控；且 Hy-MT3 发布后它的老挝语独占价值不复存在。

保留的兜底预案（非默认，仅当盲测暴露短板时启用）：

| 角色                       | 模型           | 选型理由                                             |
| -------------------------- | -------------- | ---------------------------------------------------- |
| 老挝语兜底（盲测不达标时） | Sailor2-8B/20B | Apache-2.0，老挝语有 400B SEA 语料持续预训练的独立证据 |
| 大杯质量增强（可选）       | Hy-MT3-30B-A3B | MoE 仅激活 3B，官方称超多家旗舰非思考模式            |
| 多语对话/兜底              | Sailor2-20B    | 通用能力 + 15 语言全覆盖                             |
| 轻量边缘场景               | Hy-MT3-1.8B    | 同代小杯，量化后 ~440MB                              |

# 5. FLORES+ 盲测实录

选型报告的所有"官方称 XX 超 YY"都是厂商自报，而且低资源语言的自动分（BLEU/chrF）可能虚高。所以上线前用真实可复现的公开语料自建了盲测：**FLORES+ devtest 1012 句中文源文**，官方 prompt 与推理参数（temperature 0.7 / top_p 0.6 / top_k 20 / rep_penalty 1.05），vLLM 部署于局域网 GPU 机器，batch 端点整语言一次请求。实测 0.22s/句，8 语言约 30 分钟跑完，8096 句零失败。

评分用两个指标：chrF++（sacrebleu，字符 n-gram 表面重合度）+ COMET（wmt22-comet-da，语义级，模拟人类打分）。

## 5.1 总分

| 语言     | chrF++ | COMET  | 备注                       |
| -------- | ------ | ------ | -------------------------- |
| 印尼语   | 54.85  | 0.8906 | 全场最佳                  |
| 越南语   | 51.16  | 0.8890 |                            |
| 泰语     | 42.22  | 0.8767 |                            |
| 缅甸语   | 38.76  | 0.8767 | chrF 低是文字系统假象，见 5.2 |
| 马来语   | 52.81  | 0.8701 |                            |
| 高棉语   | 33.44  | 0.8331 |                            |
| 菲律宾语 | 50.76  | 0.8270 | chrF 有虚高，见 5.2        |
| 老挝语   | 37.13  | 0.8249 | 双垫底，符合"新增语言"预期 |

读这张表先记住一条：**横向排序看 COMET，chrF 只做底线参照**。chrF 是字符重合度，字母表大的文字（缅/柬/老）天然吃亏；COMET 是语义级评分，跨文字系统可比。绝对水平上（wmt22-comet-da 量纲）全部 ≥0.82，印尼/越接近 0.89 已属"接近人工"区间。

## 5.2 chrF 与 COMET 背离的实审

两个指标背离最大的三语做了低分句抽查 + 中段抽样人工复核，这里展开讲——这三段是整个盲测里最有含金量的发现。

**缅甸语（chrF 假性垫底）——实际 ≈ 泰语水平。** 低分池里多句模型译文反而比参考译文好：有一句参考本身语义混乱、一句参考漏译整句、一句把"2 个六分球"写成"2 年"。真实模型错误仅零星词汇（长颈鹿误译为"猫头鹰"、蜻蜓/蜉蝣用音译而未用地道缅语词）。**放心用。**

**菲律宾语（COMET 倒数第二）——流畅度全语料最佳。** 丢分集中在专名回译失败：「创智赢家」没识别出是 Shark Tank、人名还原错误、Oldsmobile 拼成 "Ozymobile"；另有术语错两处及一处中文词未翻译混入译文。参考译文自身含乱码，COMET 对菲语存在系统性冤枉。

**老挝语（双指标垫底）——平均可用，尾部错误密度显著高。** 中段抽查（医学/历史/地理各 1 句）全部正确且地道，但低分池里真词错密集（咆哮译成"白声"、交通系统译成"交际系统"、泰式拼写混入老挝文），并有**全语料唯一一次灾难性复读**——板球术语句触发 "ເອນນີ" 重复数百次直至 token 上限，rep_penalty 1.05 没拦住。

## 5.3 三指标合议：大模型模拟人工评审

自动分之外，又补了一轮大模型模拟人工评审：每语言随机 30 句（seed=42 可复现），逐句审错译/漏译/专名/流畅度后折算 DA 风格分。两个独立评审（GLM-5.3 与 GPT-6 Luna）对同一批句子分别打分，判断以中文源文为准、参考译文仅作辅助——避免把参考译文自身的错误算到模型头上。

**三种分数量纲不同，绝对值不可互比**：chrF++ 满分 100 测表面重合；COMET 满分 1 测语义；LLM 模拟满分 100，90+ 接近人工仅微瑕，80-89 可用少量后编，70-79 需常规人工后编，<70 不可直接用。

| 语言     | chrF++ | COMET  | GLM-5.3 人工模拟 | GPT-6 Luna 人工模拟 |
| -------- | ------ | ------ | ---------------- | ------------------- |
| 印尼语   | 54.85  | 0.8906 | **93**           | **94**              |
| 越南语   | 51.16  | 0.8890 | **91**           | **91**              |
| 菲律宾语 | 50.76  | 0.8270 | **90**           | **89**              |
| 泰语     | 42.22  | 0.8767 | **87**           | **85**              |
| 马来语   | 52.81  | 0.8701 | **84**           | **82**              |
| 缅甸语   | 38.76  | 0.8767 | **84**           | **80**              |
| 高棉语   | 33.44  | 0.8331 | **82**           | **81**              |
| 老挝语   | 37.13  | 0.8249 | **78**           | **73**              |

三指标交叉验证了两条 5.2 的实审结论：菲律宾语 LLM 打分第 3 而 COMET 第 7（"参考译文冤枉"成立）；缅甸语 LLM 与泰语同档而 chrF 垫底（"文字系统假象"成立）。

评审还实锤了一个**跨语言共性失败模式**：「空中铁匠」（Aerosmith）在缅/柬双拆错、「大雅茅斯」（Great Yarmouth）在马来/泰语双错——同一个中文音译专名在哪都翻车。根源是中文音译源文丢失了原文形，这是知识对齐问题，与目标语种无关。

> [!NOTE]
> 评审边界：大模型模拟评审不是母语者审校，缅甸语/高棉语/老挝语等低资源语种的分数只作第二意见，不能替代母语审校。

## 5.4 盲测结论

**Hy-MT3-7B 单模型方案通过盲测**，且实际表现优于自动分显示。分三档：

- **拉丁文字四语**（印尼/越南/菲/马来，82-94）：接近人工，日常/商务文体可直接上线
- **泰/缅/柬**（80-87）：可靠，错误集中在专名与专域术语（板球/乐理/滑雪），批量场景抽检专名即可
- **老挝语**（73-78）：唯一需人工后编流程

可靠性整体优秀：8096 句零失败，仅 1 次灾难性复读。

# 6. 上线前动作清单

盲测通过不等于直接上线，剩下的动作收敛为几件：

1. **专名表预处理**——全语言受益，专名翻车的唯一根治手段。中文音译源文丢失原文形，业务文本专名密度高时必须建表预处理
2. **老挝语人工后编流程**——或先跑一轮 Sailor2 同题对照（管线已就绪，复跑约 30 分钟）再定
3. **业务真实语料回译比对**——FLORES+ 是新闻体，业务文体的专名密度和术语分布可能不同
4. **工程链路实测**——泰文/缅甸文无空格分词、缅甸文组合字符渲染，OCR 与排版需实测；确认部署栈版本（transformers >= 5.6.0、vLLM/SGLang 源码编译、GGUF 的 STQ kernel）
5. **可选加固**——translate 加复读检测（重复 4-gram 超阈值单句重试），那一次老挝语复读就拦得住

# 7. 一点选型方法论

复盘这次调研，有两点值得沉淀：

**其一，选型要盯"证据链"而非"官方声称"。** 这四个候选个个都有"超 XX 旗舰"的自报战绩，但证据硬度完全不同：Hunyuan 系有 WMT25 受限组 30/31 第一的第三方可比战绩，GemmaX2 只有 28 语平均的自报分，Hy-MT3 的新增语言则完全没有单项证据。同一条"官方称"，含金量差好几个量级。

**其二，指标背离处就是洞察所在。** 缅甸语 chrF 垫底但 COMET 与泰语同档、菲律宾语 COMET 倒数但 LLM 评审第 3——单看任何一个指标都会做出错误决策。chrF、COMET、LLM 模拟评审三个量纲互为校验，背离的地方人工实审，才把真实质量水位摸了出来。如果只跑一个自动分就拍板，缅甸语可能被冤杀、老挝语的风险可能被低估。
